# Историческая модель и редактура

Сущности `HistoricalPeriod`, `HistoricalEvent`, `Person`, `Dynasty`, `HistoricalPlace`, `Province`, `Battle`, `Article`, `MuseumObject`, `HistoricalSource`, `MapDataset` описаны в `src/lib/schema.ts`. Часть полей общей сериализованной сущности опциональна; проверки `scripts/validate.ts` требуют обязательные поля в зависимости от типа.

ID не зависит от отображаемого заголовка. Все `relatedIds`, `sourceIds`, `periodIds`, `commanders`, `placeId` проверяются. Обратные связи вычисляются, названия разрешаются через каталог. Переименование заголовка не требует изменения ссылок. Удаление ID с входящими связями ломает сборку. При изменении самого ID нужен сознательный перенос связей и redirect старого URL.

Годы — целые числа: отрицательные до н. э., положительные н. э., ноль запрещён. `endYear` хранит диапазон, `approximate` — приблизительность, `month`/`day` — частичные подробности, `label` — оговорку, которую нельзя выразить одним годом. Для сортировки используется непрерывная шкала `chronologicalYear`, где 1 до н. э. непосредственно предшествует 1 н. э. JS Date не применяется. Структура не пытается конвертировать античные календари без доказательств.

## Добавить статью

1. Завести запись `article` со стабильным ID, `draft`, темой, связями и предварительными источниками.
2. Создать MDX с тем же `entityId`, заголовком и описанием. Использовать h2 для оглавления.
3. Сопоставить существенные утверждения с доступными источниками. Указать книги/главы только если они проверены. Не выдумывать страницы и цитаты.
4. `needs_review` означает, что текст ещё не готов к публикации. После реальной редакционной сверки записать дату, её пределы и ссылки в `review`; перевести и запись, и MDX в `verified`.
5. Запустить проверки. Публичный граф не может ссылаться на неопубликованную сущность.

`verified` в этой редакции означает первичную редакционную сверку, не peer review. Публичное пояснение на `/about/` сохраняет это различие.

## Музейный объект

Проверить индивидуальную запись, `isPublicDomain`, URL изображения, музей, идентификатор, материал, датировку и размеры. `findspot` — археологическое происхождение; `provenance` — формулировка поступления в музей. Не смешивать эти значения. Неизвестные сведения помечать явно. Русская датировка должна соответствовать оригиналу, который сохраняется в снимке API. Лицензия изображения не выводится из возраста античного предмета.

## Географическое место

Проверить совпадение Pleiades ID с названием и описанием до использования координаты. Поле reprPoint — обзорная представительная точка; оно не доказывает точное положение события или сооружения. Сохранить авторов, URL, дату получения, лицензию и ограничения точности. Нельзя переносить современный топоним на произвольный древний период без оговорки.
